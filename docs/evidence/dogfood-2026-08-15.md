# Dogfood Report — leitir 0.1.1 (main @ 912bd13) as an external user

**Date:** 2026-08-15 · **Agent:** independent dogfooding agent (#42 gate)
**Method:** fresh venv, `pip install git+https://github.com/anthonykewl20/leitir.git` (resolved to
912bd13, wheel `leitir-0.1.1`), Python 3.14.6, Linux. Everything driven only through README.md,
`--help`, and error messages. Work area: `/tmp/opencode/dogfood` (isolated corpus root via
`--root` / `LEITIR_HOME`; the repo checkout was used read-only to diagnose root causes after a
failure was observed). One accidental write to the default `~/.leitir` occurred (see F1); it was
reverted with `leitir remove npm:zod@3.22.0`.

## (a) What worked (brief)

- **Install**: `pip install git+...` is fast (~5 s), stdlib-only as claimed; `leitir --version` → `leitir 0.1.1`.
- **`get`/`info`** on npm, PyPI, and github specs (with a token): provenance manifests are rich
  and honest (`parity: drift` with `only_in_git: 213`, checksums, timestamps). `info` one-shot
  context matches the README screenshots (223 ast symbols for markdown-it-py, examples, trust).
- **Scoped `search` + `index` on git-commit shelves**: excellent output — human summary on
  stderr, full JSON on stdout, permalink + blob SHA per match, honest
  `coverage=complete_for_declared_universe eligible=3 indexed=3`. `search --index` and
  `--require-index` semantics behave as documented.
- **`--local` flow**: `get --local` materializes under `./.leitir-refs` and even auto-manages
  `.gitignore` ("already covers .leitir-refs/").
- **`trust`, `api`, `diff`** reproduce the README screenshots (factor breakdown with evidence
  JSON, symbol index, file/API deltas).
- **`doctor`** (text + `--json`, `--no-network`): meaningful checks, sane 0/1/2 contract,
  correctly reports corpus integrity at scale (owner's corpus: 131 shelves, 0 corrupted).
- **`exit-gate-validate`** on the checkout's `benchmarks/exit-corpus/corpus-v1.1.json --json`:
  structured, honest output (`ratified: false`, `content_binding: "absent"`, per-case validity).
- **`search --global`**: runs, honestly reports `coverage=indeterminate_global`.
- **Fail-closed behavior where it matters**: tampered shelf + no network → exit 1; bad spec
  prefixes → typed error listing ALL supported forms (excellent); garbage `--policy` JSON →
  typed schema rejection; nonexistent commit → clear HTTP 404, exit 1.

## (b) Friction list

Severity: **H** = blocks a documented flow / wrong result; **M** = significant confusion or
missing capability; **L** = polish.

### H1 — Quickstart `search --package` fails on the quickstart's own package (and every README example package)

```bash
$ leitir get npm:zod@3.22.0          # works, README quickstart
$ leitir search --package zod --version 3.22.0 --ecosystem npm --must symbol_definition:parse
leitir: error: cannot safely stat local blob: .dependency-cruiser.js     # exit 3
$ leitir search --package markdown-it-py --version 3.0.0 --ecosystem pypi --must exact_text:MarkdownIt
leitir: error: cannot safely stat local blob: benchmarking/bench_core.py # exit 3
$ leitir search --package is-number --version 7.0.0 --ecosystem npm --must exact_text:isNaN
leitir: error: cannot safely stat local blob: benchmark/fixtures.js      # exit 3
```

Root cause (verified via manifest): npm/PyPI shelves store the **registry artifact** while
scoped search walks the **git tree** blob list; on `parity: drift` shelves the git-only files
(zod: 213 of them) don't exist locally → hard error. `--repo colinhacks/zod --commit <sha>`
against the same cached shelf fails identically, so drift shelves are unsearchable, period.
Both quickstart `search` lines fail; all three README screenshot packages fail. The message
names neither the shelf nor a remediation.

### H2 — `leitir bench` (quickstart) is a silent multi-minute hang that burns the whole GitHub API budget

```bash
$ leitir bench            # no --help warning; default search-v1
# ... zero bytes on stdout AND stderr for 3+ minutes (killed at 180 s; reproduced at 90 s)
```

Faulthandler trace: stuck in `tree.py:141 list_blobs_ex` → `_get_json` retry sleeping
(`clock_nanosleep`). The pinned tasks target microsoft/TypeScript, python/cpython, redis/redis
(32 tasks, 8 repos); truncated recursive trees fall back to per-subtree API crawls; 403
rate-limit responses are retried honoring `X-RateLimit-Reset` (up to an hour) — all invisible
(`logger.debug` only). Unauthenticated, this exhausts the 60 req/hr budget:
`curl api.github.com/rate_limit` → `remaining: 0`. No progress output, no token hint, no
`--dry-run`, no task filter. An external user's first `bench` is effectively an infinite hang.

### H3 — Rate-limit cascade then poisons ordinary README commands, anonymous and silent

After H2 (budget exhausted, no token):

```bash
$ leitir get pypi:markdown-it-py@3.0.0     # README screenshot command
leitir: resolving pypi:markdown-it-py@3.0.0 (cwd=...)
# ... hangs >3 min at "resolving" (killed)
$ leitir search --repo mmcloughlin/luhn --commit c26e5... --must exact_text:checksum
# fully materialized + verified local shelf, index present — still timed out >60 s
```

Same silent backoff. With `GH_TOKEN` exported: the identical search returns in **0.65 s**.
With the API endpoint dead (connection refused) and no token the cached-shelf search STILL
timed out (45 s+), i.e. the anonymous path makes a live API call even for fully cached
shelves — at odds with "reuse the same source again offline" and "scoped search serves
matching verified local shelves". Nothing ever prints "rate limited" or suggests a token;
`doctor` renders it as `[warn] network.github … 4xx (403)`.

### H4 — `bts-compute` seed selection is unusable on a real Python donor

README's own suggested donor style (`github:mmcloughlin/luhn@<sha>`):

```bash
$ leitir bts-compute mmcloughlin/luhn@c26e5... --seed-module luhn --seed-name luhn.verify --out bts-out
setup.py:5: SyntaxWarning: "\s" is an invalid escape ...     # leaked raw warning (L2)
leitir: error: seed selector matched multiple graph nodes   # exit 1
$ ... --seed-name verify      → "seed selector matched no graph node"
$ ... --seed-name checksum    → "no graph node";  luhn.checksum → "multiple"
```

Root cause (verified by dumping the graph via package internals): `test.py`'s
`from luhn import verify` creates a `declared_external` node with the same
`(module, qualified_name)` as the `donor` definition; `resolve_seed` (bts_cli.py:517-525)
matches on those two fields only and rejects ambiguity. All four public luhn functions are
imported by their own tests, so **no documented seed works**. The error never lists the
candidates; there is no `--seed-origin`/location flag; `graph.json` is only written after a
seed resolves, so there is no CLI way to discover valid seed names. Workaround that proved the
pipeline itself works: `--seed-module setup --seed-name setup.readme` (a symbol nothing
imports) → typed `status=REJECT detail_code=implicit_resource_v1` and correct
graph.json/summary.json artifacts.

### M1 — `remove` and `clean` cannot target a custom corpus root

```bash
$ leitir remove npm:zod@3.22.0 --root /tmp/opencode/dogfood/leitir-home
leitir: error: unrecognized arguments: --root /tmp/opencode/dogfood/leitir-home
```

`get/fetch/list/search/index/info/trust/api/diff/...` accept `--root`/`--local`;
`remove` and `clean` accept neither. The only workaround is the `LEITIR_HOME` env var
(engine.py:335, corpus.py:43), which the README never documents — it appears in the quickstart
only as an implied `$LEITIR_HOME` inside a `bts-run` example.

### M2 — One ineligible shelf aborts the entire `leitir index` run

```bash
$ leitir index --root $R      # corpus: zod (registry-artifact) + luhn (git-commit, exact)
leitir: error: materialized shelf is not eligible for indexed search   # exit 1, nothing indexed
$ leitir remove npm:zod@3.22.0 && leitir index
{"count": 1, "indexes": [".../luhn/c26e5.../index.json"], "schema_version": 1}
```

README says `index` builds indexes "for eligible materialized shelves" (implying ineligible
ones are skipped); instead the first ineligible shelf kills the command. The message names
neither the shelf nor which eligibility condition (source/parity/tree-hash) failed.

### M3 — Polyglot (`--language javascript`) is a five-step gauntlet with three opaque messages

1. `bts-compute jonschlinkert/is-number@98e8... --language javascript ...` on the shelf
   materialized from the npm spec → `leitir: error: donor source is not a Git commit`
   (no hint: re-materialize via `github:` spec).
2. After materializing the git-commit form: `leitir: error: cannot safely read input`
   — this is the **missing tree-sitter lock** (no `--lock`, no
   `requirements-tree-sitter.lock` in CWD). The message mentions neither the lock nor `--lock`.
3. With the lock present (copied from the repo — a pip user must know to fetch it from
   GitHub): `tree-sitter optional extra is not installed for graph production` — finally a
   good message (and `pip install 'leitir[tree-sitter]'` then works).
4. After installing the extra: seed guessing again. The JS graph for is-number contains **no
   node for the library's main export** (`isNumber`) — only module nodes and `benchmark/index`
   functions — so the natural seed can never work.
5. `--seed-module index --seed-name index` (module node) runs to completion but rejects with
   `detail_code=invalid_or_ambiguous_seed_v1` (module is not a callable member — fair, but
   undiscoverable).

### M4 — Tamper behavior: online = silent self-heal (exit 0); offline = correct rejection with a bare message

```bash
$ echo '# tampered' >> .../luhn/c26e5.../luhn.py
$ leitir info github:mmcloughlin/luhn@c26e5...
leitir WARNING leitir.materialize: materialized tree hash verification failed ...
leitir: materializing github:mmcloughlin/luhn@c26e5...     # shelf silently reverted
# exit 0, full success output; local edits to a shelf are silently overwritten
```

With the network down (dead API base URL): exit 1, but the message is a bare
`TreeReadError` — no path, no cause. README says mismatches "remove or reject materialization";
the heal path is undocumented (it is safe if re-verification succeeds, but nothing tells the
user their bytes were replaced, and `doctor` advertises tamper detection without mentioning
healing).

### M5 — `analysis-architecture --subject` validates nothing and echoes authoritative-looking digests

```bash
$ leitir analysis-architecture bts-out/graph.json --subject zzz-bogus-nonsense --json
{"status": "compatible", "subject": {"bts_digest": "sha256:91e7338f...", "candidate_key": ["zzz-bogus-nonsense"], ...}}
```

Any string is accepted; `bts_digest`/`candidate_manifest_digest` are derived from the label,
so the output *looks* bound to a real candidate but isn't checked against anything. README's
only guidance is the example `--subject widget`. An agent consuming this JSON will over-trust it.

### M6 — Quickstart mixes checkout-only surfaces into the pip-install flow

- `leitir exit-gate-validate benchmarks/exit-corpus/corpus-v1.1.json` — path does not exist
  for pip users (wheel ships only `search-v1`, `corpus-v1`, `ast-vs-regex-v1`); error is the
  generic `cannot read exit corpus manifest`. Works only from a checkout.
- `PYTHONPATH=src python tools/run_bts_tasks.py --dry-run` — checkout-only.
- `--root "$LEITIR_HOME"` — `$LEITIR_HOME` is never introduced.
- `bts-funnel --spec capability.json --recipient-manifest recipient.json --stages stages.json`
  — none of these formats are linked or described anywhere in README (missing-file error is
  fine: `could not read capability.json`).

### M7 — Token/credential discoverability fails exactly when needed

Env names (`GH_TOKEN`/`GITHUB_TOKEN`, found in credentials.py:11-12) are not in README — only
in docs/ci.md (CI canary context). `gh` CLI keyring auth (extremely common) is not bridged.
`doctor`'s `network.github 403` warning and the update-check warning don't mention rate limits
or tokens. Anonymous-first is a documented design choice, but the escape hatch is invisible at
the moment H2/H3 strike.

### Low-severity items

- **L1** `get not-a-spec` is treated as an npm package name (`npm registry lookup failed for
  not-a-spec: HTTP 404`) instead of an unrecognized-spec error; contrast `zzz:foo@1.0.0`,
  which produces an excellent supported-forms message.
- **L2** `setup.py:5: SyntaxWarning: "\s" is an invalid escape` leaks to stderr from python
  graph production (donor byte fidelity over warning hygiene is fine, but it should be
  captured/labeled).
- **L3** `--debug` adds no output whatsoever for the bts-compute seed failures (and little in
  general on this path).
- **L4** `doctor` (network mode) warns `network.crates … 4xx (404)` — crates.io root returns
  404 when healthy; noisy false warning. (Same run: `update.available` warn is a rate-limit
  side effect.)
- **L5** `exit-gate-validate missing.json` → `cannot read exit corpus manifest` without naming
  the path/errno; same pattern in a few other readers.
- **L6** `bts-compute` exits 0 on `status=REJECT` (artifacts written; status only in output).
  Probably intentional, but undocumented — scripts cannot branch on exit code.
- **L7** README trust screenshot (56, age unknown) no longer reproduces (64, age known) —
  screenshots age; consider regenerating or annotating.
- **L8** Non-`--json` scoped search prints full JSON to stdout and the human summary to
  stderr — actually nice for piping, but undocumented (I only confirmed by stream-splitting).
- **L9** Default corpus root is `~/.leitir` with no prompt; a user following the quickstart
  verbatim writes into their home before learning about `--root`/`--local`/`LEITIR_HOME`
  (which is how this run dirtied the owner's real corpus — reverted).

## (c) Top issues, severity-ranked

1. **H1** scoped `search --package` broken on all registry-artifact (drift) shelves — both
   quickstart search lines fail on the quickstart's own package; cryptic `cannot safely stat
   local blob` exit 3.
2. **H2** `leitir bench` silent hang + exhausts anonymous GitHub API budget (32 tasks over
   cpython/TypeScript/redis; per-subtree crawls; silent `X-RateLimit-Reset` backoff).
3. **H3** rate-limit cascade silently hangs `get`/`search` (incl. cached shelves, anonymous
   path) with no rate-limit/token message — the offline-reuse promise fails in this state.
4. **H4** `bts-compute` seed selector cannot address any test-imported symbol on a real donor;
   no candidate listing, no graph dump, no disambiguating flag.
5. **M2** `index` all-or-nothing on first ineligible shelf, message names nothing.
6. **M1** `remove`/`clean` lack `--root`/`--local`; `LEITIR_HOME` undocumented.
7. **M3** polyglot chain: `donor source is not a Git commit` (no hint) → `cannot safely read
   input` (missing lock, meaningless) → no nodes for JS main exports.
8. **M5** `analysis-architecture --subject` accepts anything, emits pseudo-bound digests.
9. **M4** tamper → silent self-heal exit 0 online (undocumented), bare `TreeReadError` offline.
10. **M6/M7** checkout-only quickstart lines; token env names undiscoverable.

## (d) Verdict — would an external user succeed?

**Partially. For the core agent workflow (`get` → `info`/`api`/`trust`/`examples`/`diff`,
plus scoped search/index on git-commit shelves), yes — genuinely good, honest, well-structured
output, and it works offline once materialized (with the H3 caveat).**

**But the README's own quickstart contains two lines that fail as written (`search --package
zod …` exit 3; `bench` silent hang), one that only works from a checkout
(`exit-gate-validate benchmarks/…`), one that requires an undefined `$LEITIR_HOME`, and the
BTS leg (`bts-compute`) cannot be driven on a realistic donor without reading source code
(seed ambiguity + no node listing). A first-time anonymous user who follows the quickstart in
order will, within ten minutes, hit an unexplained hard error (H1) and then a multi-minute
silent hang (H2) that degrades every subsequent command (H3).**

Success probability, honestly: install + materialize + info: **high**; quickstart verbatim
end-to-end: **low**; BTS compute without insider knowledge: **near zero**.

Recommended first fixes (highest leverage): (1) make scoped search skip git-only blobs on
drift shelves (or error naming the shelf + "materialize via github: spec"); (2) print
rate-limit state and `GH_TOKEN` guidance on 403 backoff, and cap anonymous retry sleep with a
visible message; (3) teach `index`/`bts-compute` errors to name the offending shelf /
candidates; (4) add `--seed-origin` or list candidates on ambiguity; (5) bridge or document
token env names in README; (6) gate `bench` with a network/token warning and per-task progress.
