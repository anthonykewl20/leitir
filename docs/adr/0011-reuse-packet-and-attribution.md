# ADR-0011: Reuse packet and attribution

- Status: Accepted
- Implementation: not-started
- Deciders: leitir maintainers; consensus reviewers (consensus-luna, consensus-terra)
- Date: 2026-08-11
- Technical Story: Epic #52; C5 and D1 (#71, #72)
- Proposed repository filename: `docs/adr/0011-reuse-packet-and-attribution.md`

## Context and Problem Statement

ADR-0008 defines a deterministic, content-addressed Behavioral Transplant Set
(BTS), and ADR-0009 defines relocation and validation of a `COMPLETE` BTS. They
do not define the public packet delivered to a recipient, the distinction
between citation and redistribution, or the evidence and obligations required
for every source-bearing byte.

This decision defines two deterministic packet profiles: a metadata-only
**reference packet**, and a source-bearing **reuse packet**. It also defines a
fail-closed, per-source license resolver, a reviewed compatibility policy, and a
closed machine-readable obligations manifest. The implementation belongs in
`transplant.py`; the artifact remains a BTS packet and is not a dependency
closure.

## Decision Drivers

- Only a recomputed ADR-0008 `COMPLETE` BTS with a matching accepted ADR-0009
  validation receipt may be represented as reusable.
- A reference must support review and reacquisition without carrying donor,
  adapter, probe, test, harness, license-text, or other source bytes.
- A reuse packet must bind every member, relocated/generated byte, original and
  rewritten test, adapter, probe, harness file, license decision, and obligation.
- No source-bearing byte may be bundled under missing, ambiguous, unsupported,
  or recipient-incompatible licensing evidence.
- License resolution must use only locked, verified source bytes and explicit
  REUSE-3.3 precedence; filenames and host paths are not authority.
- Legal evidence and obligations must be closed and machine-checkable.
  `ATTRIBUTION.md` is only a deterministic rendering.
- Identical canonical inputs must produce byte-identical logical packets and
  uncompressed USTAR archives across host, locale, CWD, input order, and
  `PYTHONHASHSEED`.
- Every parser, loader, and archive operation must be prospectively bounded by
  one content-addressed, corpus-measured packet policy.
- Missing, extra, malformed, duplicated, aliased, conflicting, unsupported, or
  digest-mismatched input rejects with a named `BTSRejectReason`.
- Runtime code remains stdlib-only, fully typed Python 3.11+ and uses
  `from __future__ import annotations`.
- Digests establish integrity and subject binding, not identity, ownership,
  authenticity, legal correctness, or legal advice.

## Considered Options

- Publish only ADR-0008/0009 records.
- Publish one packet that always embeds source bytes.
- Publish separate metadata-only reference and source-bearing reuse profiles
  under one closed container contract (chosen).
- Use gzip-compressed tar for v1.
- Use uncompressed deterministic USTAR for v1 (chosen).
- Reuse repository-level or existing SBOM license inference.
- Resolve every contributing source from verified bytes under a pinned REUSE
  grammar, catalog, compatibility policy, and obligations policy (chosen).
- Make `ATTRIBUTION.md` authoritative.
- Make canonical `obligations.json` authoritative and render Markdown from it
  (chosen).

## Decision Outcome

Chosen option: "two content-addressed packet profiles, uncompressed canonical
USTAR, and a fail-closed per-source attribution gate", because it separates
citation from redistribution while providing one deterministic integrity,
policy, and obligations boundary for reusable bytes.

### 1. Authorization and packet contract

`transplant.py` accepts validated frozen records, never loose paths or caller
assertions. Normative records are frozen, slotted dataclasses; enums serialize
by `.value`; unions have closed tags. Unknown fields, tags, enum values, schema
versions, duplicate JSON keys, unbounded integers, and duplicate exhaustive
ordering keys reject.

```python
from __future__ import annotations

from dataclasses import dataclass
from enum import Enum

class PacketKind(str, Enum):
    REFERENCE = "reference"
    REUSE = "reuse"

@dataclass(frozen=True, slots=True)
class PacketInputs:
    schema_version: str
    kind: PacketKind
    selection_digest: str
    donor: DonorProvenanceEvidence
    bts_digest: str
    member_equivalence_digest: str
    validation_digest: str
    recipient_license_policy_digest: str
    bundled_license_policy_digest: str
    packet_policy_digest: str

@dataclass(frozen=True, slots=True)
class ReusePacket:
    schema_version: str
    inputs: PacketInputs
    files: tuple[PacketFile, ...]
    obligations_digest: str
    bundle_digest: str

def build_packet(
    selection: AcceptedSelection,
    bts: BTSResult,
    validation: TransplantValidationReport,
    staging: ValidatedStagingTree,
    recipient_license_policy: RecipientLicensePolicy,
    bundled_license_policy: BundledLicensePolicy,
    packet_policy: PacketPolicy,
    kind: PacketKind,
) -> ReusePacket: ...
```

`BundledLicensePolicy.content_digest` covers the complete canonical policy:
policy authority/version, SPDX grammar and catalog, evidence resolver rules,
reviewed compatibility matrix, all obligation rules/templates, canonical
license-text digests, notice rules, and rejection semantics. Component digests
may remain diagnostic, but cannot substitute for this full digest.

Before construction, the boundary independently recomputes or validates:

1. the exact donor generation and full `materialized_tree_hash` under the
   locked-read discipline of ADR-0008;
2. an ADR-0008 `BTSStatus.COMPLETE` result with a non-null BTS and matching
   authorizing `bts_digest`;
3. an ADR-0009 `ValidationStatus.COMPLETE` receipt with the same donor and BTS,
   including validated E1 staging manifests; and
4. the accepted ADR-0010 selection, when present, whose chosen BTS and recipient
   profile match this packet.

`PARTIAL`, `REJECT`, a validation abort envelope, an unaccepted report, or any
cross-record mismatch cannot produce either profile. `packet.json` binds the
selected candidate, selection evidence, BTS dispositions, provenance, license
result, validation identity, and all policy digests. ADR-0010 remains authority
for selection and recipient suitability; this ADR only validates and binds it.

### 2. Public layout and profile capability

V1 uses format `leitir-transplant-bundle-v1` with one root:

```text
leitir-transplant-bundle-v1/
  bundle.json
  packet-policy.json
  packet.json
  donor.json
  bts.json
  validation.json
  obligations.json
  ATTRIBUTION.md
  members/                 # reuse only; exact BTS member spans
  source/                  # reuse only; E1 relocated production tree
  adapters/                # reuse only
  tests/original/          # reuse only; exact original donor test bytes
  tests/rewritten/         # reuse only
  probes/                  # reuse only
  harness/                 # reuse only; required non-native bytes
  licenses/                # reuse only; required texts and notices
```

Empty directories other than the required root/derived parents are not members.
Every regular archive member other than self-describing `bundle.json` is declared
by exactly one `PacketFile`; directory entries are derived uniquely from those
file paths. `bundle.json` is instead validated by canonical reconstruction, so
there is no self-referential file hash. Every `INCLUDE` member has one
`members/<member-key>.bin`, where `member-key` is lowercase SHA-256 of canonical
`NodeId` and `SourceRef`. Its record includes the full source reference,
one-based line and zero-based UTF-8-byte-column bounds, extraction algorithm,
size, and byte digest. Bytes are cut from a reverified donor blob without
normalization. Overlapping members remain separate evidence records.

A **reference packet is metadata-only**. It contains the eight required metadata
files above and no other files. In particular, it contains no donor bytes and no
adapter, probe, test, harness, notice, or license-text bytes. It carries only
closed identities, digests, findings, and pinned reacquisition pointers. It is a
non-executable, non-promotable review/citation artifact. To use it, a consumer
must reacquire all named inputs, verify the donor generation under ADR-0006/0008,
recompute the BTS, rerun ADR-0009, reevaluate current license policy, and build a
new reuse packet. Unknown-license references are permitted only with top-level
capability `review_only`; they have no execution, relocation, redistribution, or
promotion path.

Reference schemas are source-byte-free by construction. Their complete scalar
types are bounded integers, booleans, enum values, lowercase digests, canonical
SPDX expressions, strict relative POSIX paths, constrained identifiers, and
structured `PinnedSourcePointer` fields (`scheme`, `authority`, `repository_id`,
`commit_sha`, `path`, `blob_sha`). There is no generic text, bytes, base64, hex
payload, data URI, patch, source excerpt, exception text, or extension map.
Identifiers and pointer components have pinned ASCII grammars and finite lengths;
NUL, CR/LF, escapes, percent-encoded payloads, and unknown schemes reject.
Reference `obligations.json` uses this separate closed record:

```python
@dataclass(frozen=True, slots=True)
class ReferenceObligationRecord:
    obligation_kind: str       # closed ObligationKind value
    subject_record_id: str
    canonical_expression: str
    policy_rule_id: str
    evidence_sha256: str
    required_payload_sha256: str | None
    pointer: PinnedSourcePointer
```

It does not use `TextObligation.normalized_text` or carry a notice, attribution,
copyright, contributor, license, or source excerpt. Reference
`ATTRIBUTION.md` is regenerated solely from those constrained identity/digest
records. An
adversarial value that does not satisfy the field's semantic grammar rejects;
metadata fields cannot be used as an alternate carrier for donor-like bytes.

A **reuse packet** contains all exact member spans, relocated source, exact
original donor tests, rewritten tests, adapters, probes, required harness bytes,
and required legal payloads. Hashes without original test bytes are sufficient
only in references. The public role mapping from ADR-0009 `staging-v1` is total,
versioned, and byte-preserving.

Each `PacketFile` has strict-UTF-8 relative POSIX `path`, closed `role`, closed
`origin` (`donor`, `leitir_catalog`, or `generated`), bounded size, fixed mode,
and `sha256:<64 lowercase hex>`. Source-bearing roles name all contributing
source/license records. Empty, `.`, or `..` components, backslash, NUL,
normalization/case-fold aliases, duplicate paths, prefix conflicts, and reserved
names reject. Symlinks, hard links, devices, FIFOs, sockets, sparse entries, PAX,
GNU extensions, and unknown USTAR types reject.

### 3. Canonical uncompressed USTAR container

V1 is an **uncompressed** deterministic POSIX USTAR byte stream. gzip and every
other compressor are deferred: CPython gzip can encode a host OS header byte,
and zlib streaming does not define one uniquely canonical bitstream. Compression
may be added only by a new format version that ratifies and digest-binds an exact
compressor implementation, version, parameters, wrapper/header bytes, and test
vectors. A nominal compression level is not enough.

The v1 writer is part of the packet schema identity and obeys all of these rules:

- enumerate declared paths by strict UTF-8 bytes, with each explicit parent
  directory before its children; insertion/filesystem order is unobservable;
- represent a directory's logical path without a trailing slash and append
  exactly one `/` only in its USTAR name field; the path-component validator
  ignores only that writer-added terminal delimiter;
- encode only type `0` regular files and type `5` directories; regular mode is
  `0644`, directory mode `0755`, uid/gid and mtime are zero, uname/gname empty;
- use magic `ustar\0`, version `00`, no link name, and zero device numbers;
- encode name/prefix using strict UTF-8 and the USTAR 100-byte name/155-byte
  prefix split at an existing `/`; reject if no exact split fits;
- encode mode, uid, gid, size, and mtime as zero-padded ASCII octal with terminal
  NUL in their standard 8/8/8/12/12-byte fields; reject overflow rather than use
  base-256, PAX, GNU long-name records, truncation, or substitution;
- compute the checksum with the eight checksum bytes treated as ASCII spaces,
  then encode six zero-padded octal digits followed by NUL and space; reject a
  value that does not fit;
- write each 512-byte header, exact file bytes, and the unique minimum number of
  zero bytes needed to reach the next 512-byte boundary; directories have size
  zero and no data block; and
- terminate with exactly two all-zero 512-byte blocks and no extra record
  padding, garbage, timestamp, filename, host identity, or trailing bytes.

Readers enforce the same representation rather than accepting all tar variants:
they stream, validate each raw header and padding byte, reject noncanonical octal
or checksum spellings, and reconstruct the archive byte-for-byte. USTAR
field-length or numeric overflow is `REJECT_BUNDLE_INVALID` with a pinned detail
code; no alternate container is attempted.

Normative writer vectors are published with the implementation and CI verifies
them byte-for-byte on every supported Python. The first vectors, under the rules
above, are:

| Vector | Bytes | SHA-256 |
|---|---:|---|
| no members (two trailer blocks) | 1024 | `5f70bf18a086007016e948b04aed3b82103a36bea41755b6cddfaf10ace3c6ef` |
| regular `a.txt`, bytes `78`, then trailer | 2048 | `874ccd0a913ac231ab245e3839eceaaee457b50ede4e9c2198c177b46e445870` |
| directory `leitir-transplant-bundle-v1/`, then its `a.txt` containing `78`, then trailer | 2560 | `93dae5483010a39caa30cf4550336f519f6dbf258f6561f8dba87bfb38b2c628` |

The vector fixture publishes the complete expected bytes, not merely these
hashes. Packet-specific vectors additionally cover prefix splitting, maximum
accepted fields, and one-byte overflow rejection.

### 4. Canonical identity, policy limits, and loading

JSON uses strict UTF-8, `sort_keys=True`, `separators=(",", ":")`,
`ensure_ascii=False`, `allow_nan=False`, and exactly one LF. Values are null,
booleans, strings, or bounded integers. Floats, timestamps, absolute/host/temp
paths, filesystem order, locale, PID, wall time, and free-form child output are
forbidden. Domain maps/sets serialize as arrays sorted by exhaustive total keys;
genuine ties reject.

`bundle_digest` is lowercase `sha256:<64 hex>` over the canonical logical
identity payload with the digest field omitted. It covers format/writer identity,
packet kind, all `PacketInputs`, `obligations_digest`, and every sorted
`PacketFile` path, role, origin, mode, size, and exact-byte hash. `bundle.json`
is regenerated from that payload and the computed digest; it has no
`PacketFile` record and cannot introduce unbound fields. The digest is the
authority for packet identity. The archive filename is
`<bundle-digest-hex>.leitir-bts.tar`; it is checked but is not authority. An
optional detached `sha256:<hex>` of the final archive bytes may protect transport
and publication, but it is non-authorizing and not part of `bundle_digest`.

`packet-policy.json` is canonical `leitir-packet-policy-v1`:

```python
@dataclass(frozen=True, slots=True)
class PacketLimits:
    max_archive_bytes: int
    max_files: int
    max_total_file_bytes: int
    max_file_bytes: int
    max_path_bytes: int
    max_path_components: int
    max_archive_entries: int
    max_json_bytes: int
    max_json_depth: int
    max_json_nodes: int
    max_license_records: int
    max_license_evidence_records: int
    max_obligation_records: int
    max_obligation_links: int
    max_legal_payload_bytes: int

@dataclass(frozen=True, slots=True)
class PacketPolicy:
    schema_version: str
    authority: str
    policy_id: str
    policy_version: str
    limits: PacketLimits
    content_digest: str
```

Every value is a positive, bounded integer; booleans and floats reject. The
initial finite values must be measured over the ratified BTS corpus, independently
reviewed, and published as a release-policy artifact. They are not host defaults.
All packet construction and loading limits—including archive bytes, files,
payload bytes, paths/components, entries, JSON bytes/depth/nodes, licenses,
evidence, obligations, links, and legal bytes—derive **exclusively** from this
content-addressed policy. No CLI, environment, host library, or second defaults
table can widen or replace them.

To avoid circular unbounded parsing, a loader receives an already validated
`PacketPolicy` selected by the release/recipient policy and its expected digest
before opening the archive. It streams no more than the policy permits, then
requires byte-exact canonical `packet-policy.json` and
`PacketInputs.packet_policy_digest` equality. Each count/size is checked
prospectively before allocation, path retention, JSON descent, record insertion,
or extraction. Policy absence/mismatch rejects; the archive cannot nominate a
more permissive policy for itself.

Extraction uses a fresh sibling directory and publishes only after complete
validation. Writes follow the existing same-directory temporary file,
flush/fsync, `os.replace`, and directory-fsync discipline. A partial write emits
no canonical packet. An existing different artifact at the same digest name is
never overwritten.

### 5. Per-source license evidence over verified bytes

License evaluation covers every source-bearing reuse file: donor member spans,
relocated derivatives, original/rewritten tests, adapter shims, probes, and
executable harness source. Generated metadata is typed as metadata. Native
ADR-0009 prerequisites are not embedded and retain their own distribution policy.

ADR-0011 requires a **new per-source resolver**. It reads only bytes locked and
verified against the donor generation or a pinned Leitir catalog/release
manifest. It must not call or wrap `sbom.infer_license`: that function permits
manifest-first inference, host-path traversal, and filename inference. Only its
result-shape discipline—explicit expression/method/confidence/unknown fields—may
inform the new typed result. Filenames, host paths, installed metadata, remote
APIs, caller assertions, and fuzzy text matching have no license authority.

The resolver implements REUSE Specification 3.3 precedence for each source:

1. a valid file-header `SPDX-License-Identifier` in the source bytes;
2. the adjacent `<filename>.license` sidecar in verified bytes;
3. the uniquely applicable `REUSE.toml` annotation in verified bytes; and
4. the uniquely applicable DEP5 record in verified bytes.

All applicable evidence at a tier and scope is collected before selection. Zero
results advances to the next tier. More than one non-equivalent expression at
the same tier/scope, overlapping non-identical `REUSE.toml`/DEP5 matches, duplicate
headers, malformed evidence, or contradictory same-scope records is ambiguous
and terminal for reuse; the resolver does not choose the first result. A single
canonical result at the highest populated tier wins according to the precedence
above. Lower-precedence differences remain recorded as shadowed evidence but do
not override the selected result. Package/root applicability comes only from
ADR-0008's unique `SourceRootManifest`; filesystem proximity is not scope.

The same locked verified package scope is searched for obligation evidence.
`NOTICE*` discovery accepts only regular manifest-listed files selected by a
pinned exact basename grammar and explicit package-root applicability; copyright
headers are parsed only from the verified source file to which they apply.
Filename spelling locates a candidate but never proves its content or legal
meaning. Every accepted notice/header record contains source path, verified byte
digest, exact byte or line span, parser/rule ID, package scope, and normalized
typed fields. Ambient parent directories, host repository files, generated
metadata, and unverified bytes are invisible.

Every `LicenseEvidence` records source identity/path/digest, evidence
path/digest/span, evidence tier, parser/rule ID, package scope, canonical
expression, selected/shadowed status, and full policy digest. Generated
derivatives inherit the sorted complete set of contributing source records;
merging or rewriting cannot collapse obligations. Catalog files have independent
pinned records. Every reuse payload maps to at least one selected license record.

#### Pinned SPDX-2.3 expression grammar and canonicalization

Evidence must parse under `spdx-expression-2.3-leitir-v1`, not merely match a
bare identifier:

```text
expression  = or-expression
or-expression = and-expression *(ws "OR" ws and-expression)
and-expression = with-expression *(ws "AND" ws with-expression)
with-expression = primary [ws "WITH" ws exception-id]
primary = license-id ["+"] / license-ref / "(" expression ")"
license-ref = [document-ref ":"] "LicenseRef-" idstring
document-ref = "DocumentRef-" idstring
license-id / exception-id = exact case-sensitive ID in the digest-pinned catalog
idstring = 1*(ALPHA / DIGIT / "." / "-")
ws = 1*(SP / HTAB)
```

The tokenizer accepts SPDX whitespace around operators, rejects comments,
control characters other than grammar-significant HTAB, Unicode lookalikes,
empty groups, unknown catalog IDs, invalid `+` placement, and `WITH` on a
non-simple license term. Canonicalization parses to a
typed AST, emits exact catalog spelling, emits one ASCII space around uppercase
operators, removes redundant parentheses, and inserts parentheses only where
needed by precedence (`WITH` > `AND` > `OR`). It preserves operand order and
flattens same-operator nesting. Canonical AST equality defines evidence equality;
there is no algebraic equivalence inference or branch guessing.

The grammar recognizes valid SPDX-2.3 expressions, including `+`, `WITH`,
`AND`, `OR`, and `LicenseRef-*`, so malformed syntax is distinguished from a
well-formed expression lacking a reviewed policy rule. V1 reuse authorization is
deliberately narrower, as section 6 specifies.

### 6. Closed compatibility and obligations policy

The initial reviewed compatibility set contains only these singleton permissive
expressions:

`0BSD`, `MIT`, `ISC`, `BSD-2-Clause`, `BSD-3-Clause`, and `Apache-2.0`.

Each still requires an exact rule for the recipient's use/distribution category.
Copyleft, network copyleft, `OR`, `AND`, `WITH`, `+`, `LicenseRef-*`, and every
other expression are deferred until a reviewed compatibility and obligations
engine is ratified under a new policy digest. Syntactic recognition is not
compatibility authorization. CycloneDX or another generic SBOM cannot supply the
missing decision.

`obligations.json` uses `leitir-bts-obligations-v1`. It is a closed schema with
no free-form obligation dictionary:

The closed union is exactly `TextObligation | LicenseTextObligation |
SourceDisclosureObligation | ModificationMarkingObligation |
CopyleftBoundaryObligation`; that union is `ObligationRecord` above.
`TextObligation.kind` is restricted to the four
SPDX evidence fields it represents: `FileCopyrightText`, `FileNotice`,
`FileContributor`, and `FileAttributionText`. Each individual field occurrence
has its own record and provenance; omission, aggregation without provenance, or
`NOASSERTION` is invalid. Exact license texts, disclosure trigger/scope/action,
modification marking, file/library/combined-work copyleft, and network-copyleft
boundaries are therefore explicit and machine-checkable.

The compatibility catalog maps every accepted SPDX expression and recipient
use category to an exact compatibility decision, complete obligation-rule IDs,
and approved canonical license-text digests. The obligations-policy validator
proves that every evidence field and policy-required obligation produced exactly
one applicable record or an intentional policy-declared deduplication link.
Any license condition that cannot be represented by this closed union is
unsupported and rejects reuse; prose fallback is forbidden.

For reuse, each required legal payload appears exactly once under
`licenses/<content-sha256>.<role>`, byte-exact from verified evidence or the
approved catalog. Shared texts deduplicate only by digest while each source
keeps its provenance link. Missing, changed, surplus, or unreferenced payloads
reject. References carry only legal identities/digests/pointers, never these
bytes.

`ATTRIBUTION.md` is rendered solely from `obligations.json` with fixed headings,
ordering, escaping, UTF-8, and LF. The loader regenerates it and requires byte
equality. It adds no facts and is neither authority nor legal advice.

License rejection classification and summary precedence are exact:

1. a known expression with a reviewed rule that the recipient policy disallows,
   or an explicit incompatible decision, is
   `REJECT_LICENSE_INCOMPATIBLE`; detail includes donor expression, recipient
   policy digest/use category, and rule ID;
2. a valid expression with no reviewed compatibility/obligations rule is
   `REJECT_LICENSE_UNKNOWN` with `detail_code="compatibility_rule_missing"`;
3. missing, malformed, ambiguous, or contradictory evidence is
   `REJECT_LICENSE_UNKNOWN` with a specific evidence detail code; and
4. a supported compatible rule whose required typed obligation or exact payload
   cannot be materialized is `REJECT_LICENSE_OBLIGATION_MISSING`.

Known recipient disallowance therefore cannot be mislabeled unknown. Precedence
selects the summary reason only; all sorted coexisting evidence remains. The
implementation slice must add `REJECT_LICENSE_UNKNOWN`,
`REJECT_LICENSE_OBLIGATION_MISSING`, and `REJECT_BUNDLE_INVALID` to the pinned
`BTSRejectReason` enum before packet code ships; using ad hoc strings is forbidden.

### 7. Precisely bounded verification claim

A reuse packet supports **receipt verification**: a loader can validate the
USTAR representation, logical `bundle_digest`, all file hashes, policy identities,
cross-artifact subject binding, ADR-0008/0009 receipts, and materialized legal
payloads. If the exact external ADR-0009 execution prerequisites are separately
acquired and verified against the receipt—pinned nsjail binary/build, rootfs,
CPython, runner/plugin closure, execution policies, mount plans, and platform
capabilities—it can optionally rerun the included relocated source, rewritten
tests, and probes under the donor-absent rerun plan.

The packet is **not self-contained end-to-end ADR-0009 revalidation**. It does
not contain the complete verified donor snapshot or the exact donor manifests
needed to execute a fresh baseline. Original donor test bytes are included in a
reuse packet for evidence and acquisition parity, but without the verified donor
baseline tree they cannot reproduce baseline capture. External execution
artifacts are digest-pinned prerequisites, not bundled runtime dependencies.
Accordingly, packet verification cannot claim to reproduce baseline-plus-rerun;
a fresh end-to-end validation requires reacquisition and ADR-0006/0008 verification
of the exact donor snapshot plus every ADR-0009 prerequisite.

Neither profile proves occupied-recipient suitability. A reference provides only
review/reacquisition metadata; a reuse packet provides verified payload receipt
plus, conditionally, donor-absent rerun capability.

### 8. Integrity and authenticity boundary

Subject to correct hashing and validation implementations, a packet proves its
declared files are complete and byte-consistent, all records name one
digest-bound subject, a reuse packet's bytes match those authorized/validated by
ADR-0008/0009, and all declared obligation payloads are present.

It does not prove repository or publisher identity, donor ownership, source
trust, absence of malware, trusted delivery of the expected digest, correctness
of legal policy in a jurisdiction, or recipient suitability. An attacker able to
replace bytes and expected digests can replace the packet. Signatures, TUF-style
metadata, publisher identity, and trust roots are separate authenticity work.
This preserves ADR-0006's explicit **integrity-not-authenticity** boundary;
`bundle_digest`, archive-byte SHA-256, and validation receipts do not upgrade it.

### 9. Determinism and fail-closed invariants

1. Only a recomputed ADR-0008 `COMPLETE` BTS and matching accepted ADR-0009
   validation may enter packet construction.
2. V1 emits canonical uncompressed USTAR only. Compression, PAX, GNU tar, host
   tar defaults, and permissive-reader normalization are forbidden.
3. `bundle_digest` identifies the logical packet; detached archive SHA-256 is
   optional transport integrity and non-authorizing.
4. Reference packets are closed metadata-only artifacts with no source-bearing
   escape field and no execution/promotion capability.
5. Reuse packets include exact original donor test bytes and every other required
   payload; hashes alone are reference-only.
6. Every source-bearing payload has per-source verified-byte license evidence.
   `sbom.infer_license`, filenames, and host paths have no authority.
7. Valid SPDX-2.3 syntax is parsed under the pinned grammar; v1 authorization is
   restricted to six reviewed singleton permissive expressions.
8. Conflicting same-scope evidence, unknown policy, incompatibility, unsupported
   obligations, or missing payloads cannot pass the reuse gate.
9. Every SPDX obligation field and license condition has typed provenance in the
   closed union. Unknown obligation kinds reject.
10. Every loader limit derives exclusively from the digest-bound, corpus-measured
    `PacketPolicy` and is checked prospectively.
11. All collections have exhaustive total keys. Observable dict/set, filesystem,
    archive, or scheduling order is forbidden; genuine ties reject.
12. Every sad path has one named `BTSRejectReason`, pinned detail code, sorted
    evidence, and causal exception. There is no partial canonical packet or
    `except Exception: return None`.
13. Publication is atomic under the existing fsync/replace discipline.
14. Runtime is stdlib-only, fully typed Python 3.11+, deterministic, offline, and
    performs no model call or license/code synthesis.

### Upstream validation

The decision was checked against mature upstream contracts:

- pip wheel construction sorts traversal, honors `SOURCE_DATE_EPOCH`, and puts
  per-file SHA-256 values in `RECORD`. This supports explicit ordering,
  timestamps, and content hashes, but does not imply reproducibility without a
  fully pinned writer and inputs.
- GNU tar's reproducible-archive guidance uses `--sort=name`, `--mtime=@0`,
  `--owner=0`, `--group=0`, and fixed `--mode`; gzip additionally needs
  `--no-name`. This supports the normalized-header model but not cross-version
  canonical gzip, so v1 remains uncompressed.
- Nix content addressing identifies a logical filesystem-object graph rather
  than requiring one archive representation. This supports an authoritative
  logical `bundle_digest` and optional detached transport hash.
- SPDX 2.3 Annex D defines compound license expressions, including `WITH`, `+`,
  `AND`, `OR`, and license references. SPDX 3.0 canonical JSON reinforces the
  use of a pinned canonical machine representation; this ADR nevertheless keeps
  its own versioned closed JSON schema.
- REUSE 3.3 defines per-file licensing and the header, adjacent `.license`,
  `REUSE.toml`, and DEP5 precedence used by the resolver.
- CycloneDX does not define a normative license-compatibility or obligations
  engine. ADR-0011 therefore uses a specialized digest-bound obligations
  manifest rather than claiming a generic SBOM can authorize reuse.

### Positive Consequences

- Citation/review cannot accidentally carry executable or redistributable bytes.
- Reuse packets bind exact member, relocated, test, adapter, probe, harness, and
  legal bytes without overstating what can be rerun.
- Uncompressed canonical USTAR avoids compressor-version and host-header drift.
- Per-source REUSE precedence exposes vendored, test, and file-specific licensing
  instead of guessing from a repository filename.
- Closed obligations records make every accepted condition and provenance link
  machine-checkable.
- Full policy and loader-limit digests prevent ambient policy widening.

### Negative Consequences

- Uncompressed packets are larger.
- Reuse packets duplicate member spans and relocated output and must include
  exact original donor tests.
- The initial six-expression permissive policy rejects copyleft, compound, and
  custom expressions even when later review might permit them.
- Policy, license-text catalog, obligation rules, USTAR vectors, and corpus limits
  require independent maintenance and ratification.
- A packet alone cannot reproduce ADR-0009 baseline-plus-rerun validation.
- Legal-policy maintenance remains substantial and is not legal advice.

## Pros and Cons of the Options

### Records only

- Good, because it is small and avoids redistribution.
- Bad, because it cannot verify the presence of reusable source or legal payloads.

### Always embed source bytes

- Good, because one profile carries all reuse payloads.
- Bad, because review/citation would redistribute unnecessarily and imply rights
  not established by the artifact.

### Metadata-only reference and source-bearing reuse profiles

- Good, because capability is explicit and mechanically enforced.
- Good, because references require reacquisition and revalidation rather than
  unsafe in-place promotion.
- Bad, because consumers must validate two exact required-member sets.

### gzip-compressed USTAR

- Good, because archives are smaller.
- Bad, because gzip/zlib do not provide the cross-implementation byte-canonical
  stream v1 requires without pinning an exact compressor implementation.

### Uncompressed canonical USTAR

- Good, because every header, padding byte, and trailer is specified and tested.
- Bad, because transport size is larger and permissive tar tooling may emit or
  accept representations this profile must reject.

### Repository/SBOM inference

- Good, because existing inference is inexpensive and broad.
- Bad, because repository declarations, filenames, and host paths cannot prove
  per-source licensing or resolve contradictory REUSE evidence.

### Verified per-source evidence and reviewed policy

- Good, because every redistributed contributor has exact evidence and a policy
  decision.
- Bad, because ambiguous or unsupported licensing fails closed.

### Markdown as authority

- Good, because humans can read it directly.
- Bad, because completeness, provenance, and conditions cannot safely be
  validated from prose.

### Closed obligations JSON with rendered Markdown

- Good, because machines validate completeness while humans receive a stable
  view.
- Bad, because both representations must be generated and byte-checked.

## Resolved by consensus

1. **Q1:** V1 uses uncompressed deterministic USTAR; gzip is deferred pending an
   exact pinned compressor identity and new format version.
2. **Q2:** Logical `bundle_digest` is authoritative. A detached archive-byte
   SHA-256 is optional transport protection and non-authorizing.
3. **Q3:** Reference packets are metadata-only, including no adapter or probe
   bytes.
4. **Q4:** File-header SPDX evidence is most specific, followed by adjacent
   `.license`, `REUSE.toml`, and DEP5; same-scope conflicts reject as ambiguous.
5. **Q5:** Initial reviewed reuse coverage is the six singleton permissive SPDX
   expressions listed in section 6.
6. **Q6:** An unknown-license reference is explicitly `review_only`, non-reusable,
   non-executable, and non-promotable.
7. **Q7:** Reuse packets include exact original donor test bytes; only references
   may carry hashes/pointers without those bytes.
8. **Q8:** All finite `PacketLimits` are corpus-measured, content-addressed policy
   values and exclusively control construction/loading.

### Remaining open questions

None for the v1 semantic contract. The exact corpus-measured limit values,
policy/catalog digests, complete USTAR fixture bytes, and reviewed rule contents
are required ratified implementation/release artifacts, not unresolved design
choices.

## Deferred or externally owned requirements

- ADR-0010/C3b owns candidate selection and recipient suitability; ADR-0011
  embeds and binds its accepted artifact without redefining scoring.
- ADR-0009 E1-E3 own relocation, original/rewritten tests, probes, and validation.
  ADR-0011 assigns public paths and accurately limits packet revalidation claims.
- Occupied-recipient `PATCH.diff` remains deferred to the v0.1.3 occupied-
  recipient gate; v1 does not emit a misleading canonical patch.
- Recipient `allowed_licenses` and use category come from ADR-0010 C4.
  ADR-0011 owns per-payload resolution, compatibility application, obligations,
  and rejection.
- Maintainer/legal review must ratify compatibility and obligations rules. This
  ADR defines their closed interface and does not substitute AI judgment.
- Signature/TUF trust, publisher identity, and donor ownership remain separate
  authenticity work, consistent with ADR-0006, ADR-0008, and ADR-0009.
