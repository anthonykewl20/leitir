# Leitir 0.2.000

Release candidate notes — publication and final evidence are pending.

This minor release collects the capabilities and integrity corrections added
since v0.1.6. Public version `0.2.000` corresponds to Python distribution
version `0.2.0`; future corrective releases use `0.2.001`, `0.2.002`, etc.
Python 3.11 or later is required. The core runtime remains stdlib-only.

## Capabilities added since v0.1.6

- Optional MCP server exposes dependency context and source operations to MCP
  clients. `leitir.api.call_json` provides callable CLI dispatch with isolated
  concurrent warning capture.
- Agent-facing operations add corpus-wide `search --corpus`, bounded natural
  language query planning with `ask`, `usage assemble` evidence assembly, and
  compact dependency context with `info --brief`.
- Python `check` derives import roots from materialized packaging evidence.
  `diff --impact` intersects removed API symbols with resolved consumer usage;
  its distribution-name-based import-root limitation remains explicit.
- `bts-run` resolves the pinned containment descriptor automatically while
  retaining substrate authentication and fail-closed execution gates.
- `leitir.api.warm_call(root)` reuses verified materializations across calls
  with writer-visible epochs and invalidation after changes, including other
  processes.
- `bts-port-contract` generates Python-to-Go behavioral contract tests and
  attribution bound to measured donor evidence. It does not translate donor
  source or execute the Go implementation; unsupported contract cases reject.
- The self-calibration loop records fuzz and mutation findings with reproducible
  evidence. Documentation checks cover the agent-facing skill as well as CLI,
  version and installation claims.

## Correctness and integrity fixes

- BTS closure includes nested class/function runtime owners. Constructors and
  nested dependencies cannot disappear behind a containing definition. Known
  rejection survives later budget exhaustion. (#309)
- API and example caches are re-derived from verified source; changing cached
  text and its neighboring metadata cannot fabricate source evidence. (#310)
- Search citations distinguish exact Git trees from registry artifacts and
  sampled/normalized archives. Local tree hashes alone do not prove upstream
  Git identities. Go shelves share one canonical location; Git symlink contents
  are indexed without following the link. (#311)
- Query JSON preserves literal values and rejects duplicate/unknown fields;
  independent optional predicates retain independent boosts. Match provenance
  identifies AST or heuristic processing. (#312)
- PyPI source/repository links outrank funding links. Repository-free packages
  can use checksum-verified artifacts with explicit degraded provenance. (#313)
- Go requirement parsing handles valid quotes and escapes; go.mod reports
  direct dependency coverage instead of claiming a complete transitive graph. (#314)
- Python API checks follow complete qualified paths and explicit reexports.
  Conflicting aliases, shadowed bindings, unloaded module attributes and imports
  naming classes as modules remain unresolved. Version-impact reports retain
  removed imported owners through member accesses, including the real Flask
  JSONEncoder removal. (#315)
- Repeated queries reuse bounded, complete immutable Git tree listings.
  Failed/incomplete recoveries are never cached. Explicit C++ searches include
  ordinary `.h` headers. (#316, #328)
- Catalog corruption, manifest rewrites, source attribution and warm invalidation
  retain fail-closed behavior. Malformed spec diagnostics have mutation evidence.
  Platform cache isolation and concurrency validation no longer assume lock
  acquisition order. macOS CI redistributes long tests across idle workers
  while preserving the full suite and its deadline. (#306–308, #330, #334)

Release publication also binds CI to the actual tagged source: only exact-commit
push or manually dispatched builds qualify. PR merge-ref builds are excluded,
and publication waits for artifact attestation before creating the release.

## Compatibility and migration

- Some formerly complete BTS results now reject because included class bodies
  contain unresolved dependencies.
- The new Python `check` command reports unproven qualified references as
  `unresolved`. Missing or ambiguous packaging declarations produce
  `NOTHING_INDEXED` (exit 4); source-tree layout guessing is not an authority.
- Artifact, sampled and legacy shelves without exact upstream verification may
  need upstream tree access before issuing Git citations. Mismatched queried
  bytes reject. Existing source-derived info/API/example views remain available.
- Search output now includes match method provenance, which changes serialized
  report and funnel digests. Recompute downstream stored reports when upgrading.
- Go dependency output explicitly reports direct-only coverage. Do not interpret
  it as an MVS-resolved transitive dependency graph.
- Existing corrupted shelves must be re-materialized. A corrupt `sources.json`
  catalog blocks integrity-sensitive operations such as `get`, `install`,
  `lock`, `diff` and `export`; restore the catalog from backup or deliberately
  move it aside and re-add sources. Re-materializing shelf bytes alone does not
  repair the catalog. Load-time tree verification remains required.

## Release validation

Per-issue real upstream probes and before/after evidence are committed under
`docs/evidence/issue-*-2026-09-05/`. Actual probes include Packaging, Requests,
Vitest, Zod, attrs, BeautifulSoup4, published Go modules and fmt headers; they
exercise success, malformed inputs, provenance mismatches and source tampering.
Final release-commit suite, benchmark, installed-artifact and signed containment
results will be recorded before publication. No absence-of-all-defects claim is
made from these finite executions.

Contained donor execution remains explicit-opt-in and requires the independently
ratified runtime digest. Polyglot graph production is distinct from full
transplant/port execution; unsupported paths continue to reject. Go containment
remains proposed work, and generated Go contracts have no executed-Go proof.
